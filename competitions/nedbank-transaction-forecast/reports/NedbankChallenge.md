
# Nedbank Transaction Forecasting Challenge – Complete Problem Specification

## Objective
Predict `next_3m_txn_count` – the total number of bank transactions each customer will make over a future three‑month window (November 2015 through January 2016).  
This is a regression problem.

## Evaluation Metric
**Root Mean Squared Logarithmic Error (RMSLE)**  
Implemented as RMSE on log‑transformed values.  
The platform scores using RMSE on log‑transformed values, which is equivalent to RMSLE.

**Submission requirement:** You must submit the natural log of your predictions plus one.  
In Python: `np.log1p(y_pred)`. Do not submit raw predicted counts – your score will be incorrect if you do.

## Data Description
- Anonymised behavioural data for nearly 12,000 Nedbank customers.
- Up to 34 months of transaction history.
- Monthly financial snapshots.
- Cleaned demographic profiles.
- The test set contains 3,584 customers (you must predict for these).
- Real‑world characteristics:
  - High‑cardinality free‑text descriptions.
  - Partial nulls in income fields.
  - Seasonality effects (November to January holiday period).
  - Customers whose behaviour varies wildly from month to month.

## Summary of Key Technical Requirements (for Codex to know)
- **Target variable:** `next_3m_txn_count` (raw count, but submissions must be `log1p` transformed).
- **Evaluation:** RMSLE = sqrt(mean((log1p(y_true) - log1p(y_pred))^2)).
- **No data leakage:** Do not use future information when creating features for past dates.
- **Seasonality:** November–January holiday period likely affects transaction counts.
- **Missing data:** Handle partial nulls (e.g., income fields) appropriately.
- **High cardinality:** Free‑text transaction descriptions need encoding (e.g., frequency, TF‑IDF).
- **Reproducibility:** Set seed, no randomness that changes leaderboard rank.
- **Allowed packages:** Open‑source only (e.g., pandas, numpy, scikit‑learn, xgboost, lightgbm, etc.). No AutoML.
